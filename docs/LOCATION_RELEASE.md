# SWELL location evidence release

## Run
From the repository root, use Python 3.11+ and `python -m pip install -r requirements-location.txt` for the audited CAD export. Follow START_EARTH.txt to install the existing Cesium renderer and start `python run_swell.py`. Open http://127.0.0.1:8000. Select **Inspect GPS point** and click actual ground, or **Inspect map center**. The new `location.html` can also be opened directly; it accepts `?lat=...&lon=...` and browser geolocation with permission. GPS coordinates are sent to external data services only on explicit evidence fetch; browser geolocation can be approximate. The historical preview includes a coordinate-linked investigation link. Return to the main map at the selected coordinate (and optionally display retrieved USGS gauge points). The existing site grid does NOT move to an arbitrary GPS location or become valid for a new location.

## Scientific sources and method
- NOAA NWS active alerts: https://www.weather.gov/documentation/services-web-alerts — official alerts, not SWELL predictions. US only.
- USGS OGC API https://api.waterdata.usgs.gov/docs/ogcapi/migration/ — monitoring locations then latest gage height (00065). Nearest 20 candidates from up to 100 returned locations within a +/-0.25 degree search box, not a catchment match. A gage datum is not water depth at a building. No freshness guarantee; preserve observation and retrieval times.
- GloFAS v4 via https://open-meteo.com/en/docs/flood-api — regional modeled discharge (~5 km), not parcel flood depth. Public Open-Meteo service subject to its usage terms, including noncommercial use limits. AIFS rainfall via existing connector is coarse daily AI weather forecast, not local deformation AI. Current soil moisture from weather-model output is not SMAP ground truth. https://open-meteo.com/en/docs
- USDA NRCS SDA https://sdmdataaccess.nrcs.usda.gov/WebServiceHelp.aspx — point intersection with SSURGO polygons and mapunit components; US coverage, map interpretation not laboratory measurement. Soil hydrologic group does not uniquely determine CN without land cover and antecedent condition. No automatic conversion.
- NASA CMR local optical acquisition discovery reuses the existing catalog/granule APIs, using a small bounding box around the selected point. Metadata links only; imagery streaming remains the existing Cesium/GIBS/USGS/Esri implementation.
- NRCS National Engineering Handbook 630 H: https://directives.nrcs.usda.gov/sites/default/files2/1754923466/Subpart%20H%20%E2%80%93%20Estimation%20of%20Direct%20Runoff%20from%20Storm%20Rainfall.pdf . S=25400/CN−254 mm, Ia=0.2S, Q=(P−Ia)^2/(P+0.8S) above Ia, otherwise zero. The event method is empirical and mass-conserving, not a full physical routing solver. Treat selected daily inputs as one continuous storm; compute cumulative runoff in m³, compare assumed CN changes and finite storage, additional rain applied at start of event. CN ±10 is deterministic sensitivity, not probability. No spatial distribution, peak flow, sewer or flood-depth forecast. Default curve numbers and area are examples, not observed.
- Optional user supplied water depth drives simple hydrostatic pressure rho*g*h and resultant rho*g*h²/2 per unit vertical wall width. Not a structural capacity or safety determination, no load combinations or dynamic forces.
- https://github.com/USEPA/Stormwater-Management-Model (public-domain SWMM solver) is the recommended next urban drainage/network engine when actual catchments, rainfall hyetographs, pipe geometry and outfalls exist.
- https://github.com/landlab/landlab (MIT) and its overland flow component: https://github.com/landlab/landlab/blob/master/docs/source/user_guide/overland_flow_user_guide.md — established shallow-water routing with DEM, roughness, boundaries and adaptive stepping. Neither solver is integrated or bundled in this release. Need DEM vertical datum, drainage connectivity, inflow hydrographs, validation against gauges and flood extents, then spatially registered inundation layers and uncertainty. Official US flood forecast products: https://water.noaa.gov/about/api (NWPS), not yet integrated here.
- https://github.com/mozman/ezdxf (MIT) used directly via installed library for actual DXF generation, readback and audit; pyproj transforms local azimuthal equidistant coordinates, roundtrip test, WKT included. Circle is a user-defined review area, not surveyed parcel, catchment or proposed infrastructure. Export includes GeoJSON, CSV, JSON, role instructions, optional client-supplied evidence snapshot and hashes. Hashing establishes file integrity, not provider provenance authentication or professional approval. Review-area polygon crossing dateline/poles rejected. No G-code is emitted; independent CAM simulation, approved geometry, machine tool, material, stock, workholding and qualified operator approval are necessary.

## Validation and limitations
40 existing+new Python tests before hydrostatic test; final run recorded in TEST_RESULTS.txt. Browser harness uses actual local model/export functions with unavailable upstream-source test fixtures, no fabricated live measurements. It exercises evidence failure, scenario calculation and invalidation. Main Cesium integration and live APIs have not been verified from this offline sandbox. Current data interfaces are based on documented provider schemas and can fail visibly. Main renderer, existing physical model and Worlds remain unchanged except additive hooks to the HTML/preview; GPS point selection opens a separate location workspace so existing controls remain available. No certified design, engineering seal, actual parcel flood depth, surveyed structures, real NISAR processing validation or local AI model training delivered by this release. Do not use for emergency decisions: follow official warnings. Any data supplied by the user needs qualified review.
