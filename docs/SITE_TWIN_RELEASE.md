# SWELL GPS Site Twin — implementation and critical review

## Run on a connected computer

Use Python 3.11+, Node/npm (for local Cesium and Three renderers), and the commands in START_SITE_TWIN.txt. The server is a local research application, not an authenticated production service. Do not expose it to public networks; uploaded data is stored on disk. Navigate the existing Earth globe, select the GPS point, and open Site Twin. The original Earth, physics, classic, location intelligence and Worlds features remain available. A separate uncluttered site workspace is an additive choice, not a replacement of the original scientific models.

## Data connections and prerequisites

| Source | How to connect | Limitation |
|---|---|---|

| USGS 3DEP | Site Twin Load terrain (US coverage), or upload single-band metric GeoTIFF DEM with declared vertical datum | Provider sampling spacing is not native resolution; vertical datum must be checked. Upload a suitable DEM outside coverage. |
| Esri World Imagery | Site Twin aerial backdrop; existing progressive globe tiles | Acquisition time not supplied by adapter; internet and applicable service terms required. Do not interpret as current observation. |
| Surveyed/orthorectified aerial imagery | Upload georeferenced RGB GeoTIFF covering site and enter acquisition date | No fake detail or invented assets; RGB visual only. |
| Cesium ion | Optional terrain/building connection in existing Earth view; use own authorized credentials | Building/terrain coverage and availability vary; not structural-condition evidence. |
| NOAA NWS, USGS gauges, USDA soils, GloFAS, FIRMS | Existing Location Intelligence/Earth connections; FIRMS requires MAP_KEY where requested | Coverage, data latency, permissions and upstream schemas vary. |
| ECMWF AIFS | New hourly forecast via Open-Meteo; max 72 hours; no provider issue time returned | Coarse grid, modeled forcing, not observed local precipitation; no actual weather fetch verified here. |
| NASA CMR / Earthdata | Site Twin evidence discovery and earthaccess helper below | Discovery does not process, validate or download observations automatically. |

NASA registration: https://urs.earthdata.nasa.gov/ ; search: https://search.earthdata.nasa.gov/ ; CMR: https://cmr.earthdata.nasa.gov/search/ . Authorize appropriate DAAC applications when prompted. Install `python -m pip install earthaccess`; use `python nasa_download.py --collection COLLECTION_SHORT_NAME --bbox -96.82 32.75 -96.77 32.80 --start YYYY-MM-DD --end YYYY-MM-DD` to discover up to 10 granules. Add `--download` only after reviewing the hits. Login is handled by earthaccess. Never commit credentials. Download manifest contains content hashes. Check actual collection version and maturity. Catalog candidates include OPERA L3 DSWx-HLS, DSWx-S1, DISP-S1 and NISAR GUNW; there is no guarantee of coverage or validated products. OPERA water comparison accepts a user-supplied georeferenced water-class raster (0 nonwater, 1 open water); ambiguous/invalid classes are excluded. It is not a permanent-water detector or proof of flood damage.

NISAR preflight: `python nisar_preflight.py GRANULE.h5 --maturity unknown --out nisar-preflight`. The adapter checks grid coordinates, CRS, phase, coherence and connected components, exports phase (radians), coherence and component rasters, and records declared maturity and source hash. It does not invert phase into vertical displacement or certify results. Use official product documentation, metadata, correct phase convention, atmospheric/orbit correction, independent GNSS, appropriate reference and geometry. Beta products are not intended for scientific research; provisional and validated products are not interchangeable. Older ingestion code is preserved, not newly validated; independently verify hardcoded paths, grid registration, incidence and sign assumptions before use. NISAR GUNW product documentation: https://nisar-docs.asf.alaska.edu/gunw/ .

## Algorithms actually implemented

1. WGS84 coordinate -> locally metric UTM domain, exact cell-center GPS coordinates, a registered elevation grid, checked CRS/dimensions/coverage, source raster SHA-256. No terrain fallback; missing DEM blocks simulations. Requested 5–100 m grid spacing is not a claim of native detail. UTM polar/cross-dateline restrictions apply. Real aerial imagery can be registered separately.
2. Explicit finite-volume diffusive Manning screening. Face flux is proportional to depth^(5/3) times sqrt(water-surface slope)/roughness; direction follows hydraulic head. Donor storage is shared across outgoing faces and head-difference limiting reduces overshoot. Rain, infiltration and idealized drains are explicit sources/sinks. Optional continuous-event Green-Ampt infiltration uses an implicit cumulative infiltration step (capacity and suction deficit assumptions). Fixed 30-second timestep, closed boundaries, maximum 128x128 cells/72 hours. No full momentum, sewer connectivity, river boundary inflow, structures, subsurface pressure or independently validated flood depth. Grid/time convergence and boundary sensitivity must be assessed against a full hydraulic solver before decisions. Numerical limiter fraction and mass residual are reported; conservation is necessary but not evidence of predictive accuracy.
3. Hourly AIFS rainfall, saved forecast snapshot and exact coordinate matching. Baseline and intervention use identical forcing. Manual rainfall is a hypothetical scenario. Saved site/input/model run, hour replay and peak water depth; painting changes explicit drainage/infiltration parameters. Map and projected rotatable 3D terrain use same calculated depths. The surface is a terrain mesh visualization, not photorealistic building geometry or a measured subsurface twin.
4. Compare matching event-hour modeled wet mask to actual imported OPERA open-water classification on a compatible grid, avoiding unsupported classes; provide TP/FP/FN/TN, coverage and IoU. No inferred flood damage, no optical/SAR equivalence claim.
5. Hybrid residual ML: `hybrid_calibration.py history.csv --out hybrid-model.json`. CSV columns: issue_utc,target_utc,physics_depth_m,rain_mm,antecedent_moisture,observed_depth_m. One site, sensor and forecast lead, at least 100 chronologically ordered samples, antecedent moisture fraction 0–1. Inputs must have been known at issue time. 60/20/20 chronological train/validation/test, purge label overlap at boundaries, validation selects ridge penalty; holdout RMSE against physics-only, abstain on failed skill gate or extrapolation. `python hybrid_calibration.py --model hybrid-model.json --predict PHYSICS_DEPTH_M RAIN_MM MOISTURE`. No real training data included; point residual learner does not overwrite spatial mass balance; no calibrated uncertainty or operational local AI yet. Existing research panel remains structured source retrieval, not a full LLM RAG.
6. Saved-run export: GeoTIFF baseline/intervention peak depth, wet-extent GeoJSON and metric DXF polygons (>=5 cm modeling threshold, not surveyed), CRS WKT, hourly water budget CSV, scenario, optional validation metrics, role-specific HTML review report, file hashes. DXF is reopened/audited. These are draft review geometry and reproducible screening calculations, not foundation/drainage designs or professionally certified plans. No machine-ready G-code. Do not infer structural capacity from satellite pixels.

## Research and design basis (not claims of imported implementations)

- CesiumJS https://github.com/CesiumGS/cesium ; NASA Worldview https://github.com/nasa-gibs/worldview : progressive WGS84 imagery and layer separation; existing renderer retained.
- USGS National Map elevation service https://elevation.nationalmap.gov/arcgis/rest/services/3DEPElevation/ImageServer ; datum/native metadata are essential.
- de Almeida & Bates (2013), *Applicability of the local inertial approximation of the shallow water equations to flood modeling*, https://doi.org/10.1002/wrcr.20366 ; Landlab https://github.com/landlab/landlab and OverlandFlow docs. Our solver is simpler diffusive routing, NOT an implementation of their inertial solver. Upgrade to validated Landlab/full SWE with calibrated open boundaries; EPA SWMM https://github.com/USEPA/Stormwater-Management-Model for drainage networks and Green-Ampt hydrology. HEC-RAS calibration guidance: https://www.hec.usace.army.mil/confluence/rasdocs/ .
- NASA JPL OPERA https://www.jpl.nasa.gov/go/opera/ ; application examples https://github.com/OPERA-Cal-Val/OPERA_Applications . Surface water product footprint, maturity, validity masks and actual acquisition times must be respected.
- NeuralHydrology https://github.com/neuralhydrology/neuralhydrology ; Kratzert et al. https://doi.org/10.21105/joss.04050 . Informs chronological evaluation and hybrid approach, not copied or trained network. The implemented residual learner is intentionally small until real data supports a more complex model.
- NOAA National Weather Service flood event records, e.g. East Texas April 28–29 2024 (a candidate historical benchmark, not executed here); check recorded rain, measured gauge hydrographs, terrain, wet-mask acquisition coverage and land-cover changes. The 2024 event predates NISAR; use OPERA HLS if matching acquisitions are available. Separately select an actual current suitable NISAR scene to demonstrate the SAR challenge.
- NASA Space Apps official winners: https://www.spaceappschallenge.org/2024/awards/ and https://www.spaceappschallenge.org/2025/awards/ . Reviewed examples including 2plant and Eco-Metropolis; not all winners' source code was accessible. Lessons: immediate task, identifiable stakeholder, explainable NASA-to-action trace, evidence rather than feature count. No claim of judge approval or winning potential. Full official 2026 challenge text not independently retrieved; cross-check submission requirements on the official challenge portal before submission.

## Connected acceptance gates / next scientific work

A: select Dallas or a surveyed small catchment. Confirm actual imagery fetch, acquisition metadata, native DEM spacing/vertical CRS, coordinate alignment against known reference points. Verify zoom requests higher-detail tiles, not scaled thumbnails. Check data attribution and access terms.
B: use observed historical rain, exact event start, drainage/land-cover survey, gauges and water masks, not default assumptions. Calibrate on historical events and hold other storms/sites out. Report depth MAE/RMSE, gauge timing and peak errors, IoU and valid coverage, convergence vs grid and timestep, and performance against persistence/physics-only. Assimilation, forecast ensembles, uncertainty bands, open river boundaries and validated hydraulic solver are outstanding.
C: show actual NISAR change with coherent pixels, reference, LOS convention, uncertainty and independent observations. Keep detected change, possible drivers, counterfactual forecast and actual subsequent observation distinct. No SAR-to-structural safety or unverified subsurface inference. Boreholes, geotech and utility as-builts needed for site-specific hydro-mechanical model.
D: role outputs must cite every source and assumptions; professional review, design codes, surveyed geometry, loads, material properties and independent checks before construction. CNC postprocessing and machine simulation require separate verified CAD/CAM tooling and human approval.
E: browser verify connected Earth/terrain, forecast, actual data imports, 3D assets and all original navigation. This release's Chromium harness exercises actual markup/JS/backend on an explicitly synthetic terrain fixture; it does not prove live data integration. Network requests were blocked in this sandbox; no realistic local imagery, current forecast, actual NISAR run or trained local AI claim. Hyperrealistic local 3D city/subsurface and accurate engineered designs remain incomplete.
