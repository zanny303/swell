# SWELL — science-to-decision release (2026-11-14)

## Start here (Windows)
Stop the old server with Ctrl+C. Extract this archive into a separate directory. Open PowerShell in the inner `swell` directory (the directory containing `run_swell.py`). Do not overwrite your working source or data. Use Python 3.11 and Node.js LTS.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-site-twin.txt
python -m pip install earthaccess
python install_renderers.py
python run_swell.py
```

Open http://127.0.0.1:8000/ . The default is `live.html`, the new observation-first Earth workspace. `index.html` is the preserved advanced studio, including older synthetic sample data. Worlds remains separate. The same browser origin (`127.0.0.1:8000`, not localhost or a different port) can reuse the existing restricted Cesium public token. The Connections dialog saves/removes this token in local browser storage. This is not an encrypted vault. No private tokens or write permissions. Token is remembered even if the provider is currently down.

For Earthdata authenticated download, use a trusted personal machine. Authentication persistence is optional: Earthdata's `netrc` credential file is plaintext. In the active environment, run `python -c "import earthaccess; earthaccess.login(strategy='interactive', persist=True)"` once if you accept that local storage. This enables the new WTR download button. Alternatively download WTR in Earthdata Search and import the local file, without persisting credentials. Do not share `.netrc`, passwords or tokens. NASA DAAC authorization prompts may still be necessary. If using `EARTHDATA_TOKEN` instead, the current integrated button uses netrc, not the token variable; use manual downloads or the existing CLI.

## Guided real-data workflow
1. Open Earth. Real historical NASA Blue Marble is the fallback, and Cesium requests progressively detailed Esri aerial imagery at close range. Imagery date/availability is not guaranteed. EONET lists reported open events (last 30 days, capped to 250). Click one or select GPS coordinates. The point/polygon is provider metadata, not a forecast or validated hazard boundary. If remote services fail, the app shows the error. Click Prepare site twin; terrain, imagery, NASA discovery, forecast and local evidence are attempted automatically.
2. USGS 3DEP for U.S. sites; if it fails or is outside coverage, try public Copernicus GLO-30 then GLO-90. DSM includes buildings and vegetation; this is not equivalent to surveyed bare-earth DEM. All missing cells rejected; no fabricated elevations. Real land coverage only; not poles or missing ocean tiles. If needed, import a known DEM. Existing cache lasts 30 days; force refresh optional. Radius 500 m, 30 m grid by default to match OPERA posting (smaller area/shorter forecast for expensive runs). Larger-area flood routing requires catchment and river boundaries. Native pixel size and tile source hashes recorded.
3. Observe → NASA catalog. Validated NISAR GCOV and GUNW are queried by exact collection short name. ASF states validated L-band Level 0–2 collections released 2026-11-06, acquisitions from 2026-10-21 onward; don't mix maturity or processing releases without scientific justification. Early dates may require provisional products and review. The NISAR repeat interval is not continuous live surveillance. Use https://search.asf.alaska.edu/#/?dataset=NISAR&sciProducts=GCOV or https://search.earthdata.nasa.gov/ to select compatible before/after GCOV H5 files. Download to the project `nasa-downloads` folder. In Observe → Satellite change & water layers → Process downloaded NISAR GCOV pair, click Find downloaded pairs, select one, frequency and polarization, declared product maturity, Process. Large H5 files stay on disk; only the selected geographic window is read. The pair must have matching track/direction/frame/band/mode/polarization/source, release and orbit fidelity and aligned native coordinate grids. The output contains before/after gamma0 (dB) and delta dB images, native GeoTIFF windows and input hashes. Check local incidence, layover/shadow, noise, product QA and independent evidence before scientific interpretation. No automatic causal inference from intensity changes. A pair spanning the study area is required. Source acquisition may be partial or duplicated; the filename filter is necessary, not a sufficient quality certificate.
4. For independent water evidence: choose OPERA DSWx-S1 or DSWx-HLS catalog granule → Download WTR. It uses Earthdata with CMR-constrained product, site, ID and allowed source host, and a 50 MB file limit. If link/auth fails, download original WTR GeoTIFF via Earthdata Search. Enter true acquisition UTC and product, then register it. Masked, uncertain and missing categories are not treated as dry truth. Open water is blue, partial/inundated vegetation teal, masked gray, transparent dry/no data. The image is WGS84 preview, not the metric numerical grid. Click View registered layer on Earth for geographic overlay. This is surface water, not depth, and permanent water is not automatically removed. OPERA is independent from a NISAR GCOV signal; DSWx-S1 is Sentinel-1, not NISAR.
5. Simulate: rainfall from AIFS or declared scenario (manual input labelled); draw drainage/infiltration edits. Fast existing diffusive scheme is default. Optional advanced physics: 2D Saint-Venant shallow water, hydrostatic reconstruction, local Lax-Friedrichs/Rusanov flux, adaptive CFL, semi-implicit Manning friction, reflecting boundaries. This solver requires constant infiltration and no surveyed outlet (for outlet and Green-Ampt use fast solver); budget max 30,000 cell-hours. Both baseline and intervention are rerun with selected solver, with conserved volume and saved exact inputs. Numerical review replays selected solver; ensemble and plan use selected solver. Lake-at-rest and wet/dry front unit tests passed, not field validation. Test real observations, boundary conditions, spatial convergence, roughness and DEM accuracy. AIFS point precipitation is not parcel precipitation or river flood prediction. **No operational forecast or engineering certification.**
6. Verify: run timestep sensitivity and nine-scenario sensitivity (not calibrated probability). Use observed WTR comparison only for historical event with date/time matching within 1h and model posting at least as coarse as observation. Clear observed classes 0 and 1 only. It compares baseline predicted ponding to surface water, not flood attribution; permanent water can bias scores. A later field/independent observed event is needed for actual predictive skill. Retain acquisition date, product, QA, and model uncertainty in the review.
7. Act: pick stakeholder. The new review desk computes metrics from the saved model run; checklist is persisted by run and role in local browser; research citations link to the source notes. Compute alternatives runs four candidate simulations on up to 3 deepest modeled cells and sorts by wet area, peak and storage. This is constrained model screening, not an optimal engineered site design. No costs, real utility capacity, land ownership or building damage assumed. Export the existing audited GIS/DXF/CSV/HTML ZIP; plan records are included as reviews. Retained checklist UI completion is local and is not a certification or approval. Existing asset and soil CSV reviews remain available.
8. Optional science AI: `python -m pip install torch`, use site ID shown in Observe, then `python physics_ai.py --site SITE_ID --epochs 100 --out research-ai`. This experimental convolutional surrogate hard-constrains nonnegative water volume under uniform net rainfall and uses a differentiable discrete finite-volume residual and teacher supervision. It is **not** a classical continuous-coordinate PINN or a trained operational model. It uses one DEM, dry-start, at most 1h, closed boundary, no drains/interventions; tests heldout rainfall scenarios against numerical teacher and uniform baseline, checks mass/residual, saves model card. It cannot replace the solver or be activated in operations automatically. Existing local observation-trained point residual model is separate and requires independent data. Prithvi-EO optical adapter retained; actual foundation-model inference remains unintegrated.
9. Research: default bundled curated source-note corpus now works without setting environment variables. This is not full-text literature RAG. Supply your own source documents and `SWELL_LITERATURE_CORPUS` for broader retrieval, and optional installed Ollama model via `SWELL_OLLAMA_MODEL` for local generated draft. Citations are checked for known IDs, not semantic correctness; source support must be reviewed. No fabricated measurements or design authority.
10. Worlds: links to NASA PDS Orbital Data Explorer Mars/Lunar archives and USGS foundational datasets. For real terrain, MOLA / LOLA are appropriate datasets; Diviner for lunar temperatures. Current planetary terrain ingestion remains manual; no automatic global real-time planetary terrain or habitat validation.

## Critical design decisions and sources
* Challenge: Dancing with the SARs asks for interactive location-based visualization of NISAR surface change (https://www.spaceappsulaanbaatar.com/challenges; official 2026 portal https://www.spaceappschallenge.org/2026/). Do not claim generic hydrology alone satisfies the task. Demonstrate paired NISAR change, distinct independent water data, explain uncertainty, compare intervention and review plan. NASA judging dimensions are impact, creativity, validity, relevance and presentation (https://www.spaceappschallenge.org/2026/local-events/ajmer/). Project closing date November 15, 2026 11:59 PM local per official portal. Verify your team's deadlines.
* NASA ASF GCOV documentation https://nisar-docs.asf.alaska.edu/gcov/ and product maturity https://nisar-docs.asf.alaska.edu/products-overview/ — exact calibrated gamma0 power, native resolution, same product processing.
* NASA OPERA https://www.jpl.nasa.gov/go/opera/products/dswx-product-suite/ and NASA Disasters https://science.data.nasa.gov/disasters/data-gallery/opera-dswx — strict water categories, masks, data time.
* NASA EONET https://eonet.gsfc.nasa.gov/docs/v3 — provider natural-event metadata, not a risk score. NASA Worldview GitHub https://github.com/nasa-gibs/worldview — map-source/date separation, not copied software.
* Copernicus GLO-30 / GLO-90 AWS https://registry.opendata.aws/copernicus-dem/ and https://copernicus-dem-90m.s3.amazonaws.com/readme.html — public static surface models, no ocean tiles, free subject to license.
* NeurIPS Krishnapriyan et al. 2021 https://proceedings.neurips.cc/paper/2021/hash/df438e5206f31600e6ae4af72f2725f1-Abstract.html — PINN loss constraints do not guarantee accurate solutions. The new research surrogate uses an explicit hard mass constraint and heldout teacher comparison; not a reproduction of the paper.
* NASA ANUGA catalog https://software.nasa.gov/software/NPO-52605-1 and GitHub https://github.com/anuga-community/anuga_core — production-strength unstructured finite-volume solver is the next independent solver comparison; not integrated here. Hydrostatic reconstruction reference Audusse et al. 2004, SIAM J. Sci. Comput. 25(6), 2050–2065, DOI 10.1137/S1064827503431090. New code is independently implemented first-order grid solver, not ANUGA.
* NASA Prithvi-EO 2 https://github.com/NASA-IMPACT/Prithvi-EO-2.0 — optical HLS time series, not raw NISAR radar; fine-tuning requires domain-specific data. NeuralHydrology https://github.com/neuralhydrology/neuralhydrology — independent measured runoff evaluation; not installed here.
* NASA PDS ODE https://ode.rsl.wustl.edu/ — actual orbital observations and coordinate search; distinct from Earth.
