# SWELL — Earth streaming and AI forcing release

This release is an additive upgrade of SWELL-upgraded.zip. Original classic and Worlds workspaces, fit/validate/ingest Python modules, stakeholder files and physics algorithms are retained. Main Decision Studio now starts on the whole globe in map view; Split and 3D twin remain available. No generated satellite images are used. The separate historical Earth preview is a spherical orthographic geographic projection, not the professional WGS84 ellipsoid renderer. No claimed street-detail from that image. The online Cesium viewer uses WGS84.

## Run and connect
1. Extract the ZIP. `cd swell`; `python run_swell.py`; open http://127.0.0.1:8000 . Python requirements for scientific features: `python -m pip install -r requirements-earth.txt` (the core existing tests use pytest/numpy).
2. On a connected machine with Node/npm: `python install_renderers.py`. Installs pinned Cesium 1.119 and Three.js 0.128, including assets/workers/controls and license files, then rewrites the main page's CDN URLs to local assets. Keep the vendor folder. If installing fails, existing CDN references remain. This installer is not executed in the network-disabled build sandbox.
3. On the main globe use +/−, scroll, Earth/Site, 2D/3D, search (place or latitude,longitude), and the Earth streaming & forecast drawer. Use "Expand Earth map" and the restore button for unobstructed navigation. My GPS location uses browser permission and displays the reported accuracy. No location is persisted by SWELL.
4. Select Esri World Imagery (default close-up mosaic) or USGS imagery (US) for detailed imagery; zoom below 600 km camera altitude. Esri usage is subject to Esri terms. USGS imagery is a historical mosaic, not real-time. For NASA products and dates, discover GIBS WMTS products from capabilities. The source status counts successful tile responses and errors, not validated cloud-free observations. Untested initial product/date combinations can fail. Dynamic WMTS product selection uses web mercator matrix dimensions and advertised format/levels; existing WMS controls remain available. Web Mercator does not cover polar regions; primary Cesium geographic imagery remains. Optional terrain and OSM buildings remain in the existing Data connections drawer (user-supplied Cesium ion token, asset permissions).
5. USGS M2.5+ past-day GeoJSON refreshes every 2 minutes via local backend (60 s cache). Fire points: configure environment variable `FIRMS_MAP_KEY` before starting server; zoom to a region and load detections in view. Do not place a key in Git/source. Points report acquisition time and confidence and indicate thermal anomalies, not confirmed fire perimeters.
6. For uploaded GeoTIFF, use Data connections → display raster. The source is retained, explicit CRS is required, and native data are reprojected per map tile to EPSG:3857. Maximum tile detail is limited by estimated native pixel size. True-color RGB uint8 GeoTIFFs preserve color interpretation; numeric raster uses one fixed 2–98 percentile scale; masked/outside coverage stays transparent. Source hash and metadata remain. Display does not automatically assimilate numeric values. EPSG:3857 excludes the poles; antimeridian-spanning uploads require splitting first. Existing source size limit 50 MB; optional packages rasterio/numpy/Pillow.
7. Fetch AI weather for the study site in Earth streaming & forecast. Open-Meteo public endpoint serves ECMWF AIFS Single data; noncommercial usage only, obtain appropriate service access for commercial use. Forecast request uses model explicitly (no automatic alternative) and 15 day horizon. Whole UTC days starting tomorrow only; reject missing, invalid or discontinuous precipitation; apply only if at least ten complete days. The point forecast is ~0.25° forcing shared across site, not downscaled parcel weather. The provider response doesn't expose initialization time, so it is explicitly null. The fetched timestamp is not the forecast issue time. Baseline and alternative use identical AI rainfall; extra painted rainfall and drainage/paving/water-table interventions affect the alternative only. Horizon is bounded by complete forecast days; exports include the actual returned forcing, coordinates, dates and model. Clear to restore manual scenarios. Synthetic history stays synthetic; do not interpret conditional motion as a calibrated real Dallas forecast.

## Research and architecture choices
- CesiumJS (Apache-2.0): https://github.com/CesiumGS/cesium — high-precision WGS84 globe, imagery/terrain/3D Tiles streaming. Existing licensed runtime retained; no claim that external source code was cloned.
- NASA Worldview (NASA-1.3): https://github.com/nasa-gibs/worldview — example of layered scientific imagery with date controls. Its underlying GIBS services are used directly, not a screenshot or copied application.
- NASA GIBS examples: https://github.com/nasa-gibs/gibs-web-examples ; API https://nasa-gibs.github.io/gibs-api-docs/access-basics/ — discover layer IDs, tile matrix levels, date, format; no claim of imagery beyond native spatial resolution. GIBS is browse visualization, not quantitative physical data.
- USGS imagery https://basemap.nationalmap.gov/arcgis/rest/services/USGSImageryOnly/MapServer ; https://www.usgs.gov/faqs/what-are-base-map-services-or-urls-used-national-map — aerial resolution varies by coverage and acquisition; no continuous live building photography.
- USGS ComCat https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php ; NASA FIRMS https://firms.modaps.eosdis.nasa.gov/content/academy/data_api/firms_api_use.html ; NASA CMR https://cmr.earthdata.nasa.gov/search/ ; NASA ASF https://asf.alaska.edu/ .
- ECMWF open data https://www.ecmwf.int/en/forecasts/datasets/open-data ; Python retrieval alternative https://github.com/ecmwf/ecmwf-opendata ; Open-Meteo model enum https://github.com/open-meteo/open-meteo/blob/main/openapi/forecast.yml ; API docs https://open-meteo.com/en/docs/ecmwf-api . AIFS is a real machine-learning weather model, not a local displacement prediction model.

## Scientific pipeline, constraints and next acceptance gates
Observation metadata → original numerical source files → explicit CRS/units/time/quality mask → target grid and support scale → calibration using independent GNSS/levelling/LOS → holdout comparison → model state → weather forcing + intervention → physics outputs, uncertainty, scenario exports → verification against subsequent observation. Existing `swell.ingest`, `swell.validate`, `pipeline/nisar_catalog.py`, `pipeline/publish_cog.py` retained. Real NISAR GUNW ingestion is explicitly unverified in its own code; do not use unwrapped phase as absolute vertical without sign/wavelength/reference/geometry and horizontal motion assumptions. Download Earthdata-authenticated files and inspect product metadata before accepting any real-data result. NASA CMR discovery is not a measurement or successful ingest.

Existing reduced-order engine explicitly conserves water using infiltration-runoff-storage-ET-drainage-recharge-capillary input and clay response relaxation. It is not a lateral routing, groundwater flow or coupled mechanical PDE solver. For quantitative future displacement, fit hydraulic/strain parameters using measured soils and independent observations; evaluate chronological spatial holdouts against persistence and model-only baselines, report errors and uncertainty. Do not train an ML residual corrector on synthetic or leaked outcomes. Next steps require data: real NISAR/OPERA displacement + GNSS time series, soil logs, DEM/terrain, asset footprints and approved 3D Tiles/photogrammetry. Local construction and load changes, true borehole stratigraphy, 3D groundwater flow, live city-scale subsurface twins and AI residual training are not yet implemented. Existing model painting is limited to the loaded site, not arbitrary locations. The grid represents scientific model support and should not be confused with imagery resolution or asset-level certainty. No engineering safety certification.
