# SWELL engineering upgrade — additive release

## Run
From the extracted `swell` directory: `python run_swell.py` and open `http://127.0.0.1:8000/`. The original Decision Studio remains the homepage, `classic.html` retains the full original Earth application, and `worlds.html` retains the separate planetary explorer. The full Earth viewer needs access to its existing Cesium and Three.js CDN libraries. `offline.html` needs no external CDN and uses the same local study file and new screening engine; it is not a replacement for the globe. Optional GeoTIFF preview: `python -m pip install -r requirements-earth.txt`. Optional original ingestion: `python -m pip install -r requirements-api.txt h5py rasterio pyproj earthaccess`.

## What changed
- Original fitted model remains the default; choose **Water-balance screening** in Scenario lab for the additional model. The new engine feeds the existing map, 3D block, scenario chart, zone table, findings and exports through a common prediction function. Its groundwater-rise and active-depth controls modify explicit assumptions. Historical inference and existing verification tests continue to belong to the original model. No inherited fit-error band is displayed as uncertainty for the new model.
- The new engine is a reduced-order daily two-reservoir vertical column. Rainfall on permeable area is limited by conductivity and shallow storage; the residual is runoff. Evapotranspiration removes shallow water; percolation moves water to deep storage; groundwater contributes bounded capillary rise; drainage/recharge remove water. The mass budget is `Δstorage = precipitation + capillary input − runoff − ET − drain − recharge`. Linear extensibility is used as a screening shrink–swell coefficient, multiplied by active depth and an assumed restraint factor. Ground displacement relaxes exponentially toward moisture-dependent target. Baseline and scenario start at the same state. This is **not** a Richards-equation PDE, 3D groundwater solver, finite-element stress model or field-calibrated model. Parameters are explicit in `site/hydro.js`, with bounded sensitivity cases, not a probability interval. Paving can also suppress ET, so displacement need not always decrease. Extreme rainfall may produce runoff rather than more infiltration. No lateral routing.
- Added obvious 2D/3D map toggle, camera altitude, twin +/− and reset, keyboard focus, responsive refinements, clickable workflow arrows, coordinate validation, correction of the NISAR catalog command, and revised provider status labels. Existing tools and exports retained.
- Data connections panel: actual NASA CMR collection and granule metadata search over visible geographic bounds, NASA GIBS capabilities discovery and date selection, local raster preview (CRS checked, band 1, reprojected to EPSG:4326, retained with SHA-256), GeoJSON display, optional Cesium ion terrain and OSM buildings (user token and entitlements required). These are display/context features; raster previews are NOT automatic NISAR calibration or forcing ingestion. Original scientific ingestion CLI remains available. No commercial token bundled or stored by new UI. Named search still uses existing Nominatim.
- Original research assistant available in Understand as structured retrieval (not LLM RAG). Role ZIP includes current scenario zone CSV and, when using the new engine, current focused water-budget CSV. Historical stakeholder files remain and are labeled as historical; no imaginary costs, IDs, boreholes or building-safety certifications.
- Offline fallback supports genuine local grid zoom/pan, editing, physical recomputation, six evidence/decision views, section, chart, scenario JSON and per-cell CSV. Screenshots in `screenshots/` were captured in Chromium from actual offline HTML/JS and bundled site data (local inline test harness because browser navigation is blocked). They are not live NASA or main-globe captures.

## Tests and known limitations
`python -m pytest -q` (25 passed, including 20 original), `node tests/test_hydro.cjs` (passes), `node --check site/studio.js`, `node --check site/upgrade.js`, `node --check site/offline.js`. `SWELL_LOCAL_HARNESS=1 python tests/browser_offline.py` passed local Chromium interaction tests. Without that variable the script tests the real local URL on a machine that allows browser navigation. Browser and network policy prevented full main Cesium/Three.js, live NASA/USGS and Worlds browser testing here. CMR/GIBS parsers tested against explicit fixtures, not live services. Local GeoTIFF reprojection tested with a small generated fixture (not observational data). Data source remains SYNTHETIC; no new field or satellite data is present. World files are preserved, not upgraded to real planetary terrain in this release. Current 3D twin still has schematic soil layers and paving proxies, not photorealistic georeferenced subsurface or buildings. A standalone water-balance model cannot establish site safety or causation. Some external layer names from the original application may remain unverified; GIBS discovery offers provider-advertised alternatives. Real imagery display requires connectivity and actual coverage. The user needs to supply compatible actual NISAR acquisitions, rain/soil/paving data and independent validation observations, and run the existing ingest/validate pipeline before claiming real-data scientific performance.
